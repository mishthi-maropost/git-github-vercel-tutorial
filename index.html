What Git is

Git is software on your Mac that saves checkpoints of your project. It remembers what changed, when, and who saved it.

What GitHub is

GitHub is a website that hosts Git projects so people can share, review, and collaborate. Git lives on your computer. GitHub lives on the internet.

What a repository is

A repository (repo) is the project’s files plus their Git history. A local repo is on your Mac. A remote repo is hosted on GitHub.

Core takeaway

YOUR MAC → Git → GITHUB → VERCEL → LIVE WEBSITE

Code locally. Version it with Git. Store and collaborate through GitHub. Deploy through Vercel.

Chapter 4

Clone vs Fork

These are not two ways to do the same job. Clone copies a repository onto your Mac. Fork copies a GitHub repository into your GitHub account.

Git Clone

GitHub → your Mac

Clone answers: “How do I get this repository onto my Mac?”

GitHub
ani/pizza-recipe

↓ git clone

MacBook
pizza-recipe/
Terminal — samriti@MacBook-Pro

git clone https://github.com/ani/pizza-recipe.git

Cloning does not automatically give you permission to push. Anyone who can read a repository may be able to clone it. Pushing depends on GitHub permissions.

GitHub Fork

GitHub → your GitHub

Fork answers: “How do I create my own GitHub copy of someone else’s repository?”

Original
github.com/ani/pizza-recipe

↓ FORK

Mishthi’s GitHub
github.com/mishthi/pizza-recipe

↓ clone

Mishthi’s Mac
pizza-recipe/

After forking, Mishthi still clones her fork to the Mac before editing locally.

Fork happens on GitHub. Clone happens from GitHub to your Mac.

Chapter 14

Common beginner mistakes

Mistake 1 · “I cloned the repository, so I can push.”

Clone gives files. Permissions determine push access.

Mistake 2 · “I forked the repository, so the files are now on my Mac.”

Fork created a GitHub repository. Clone the fork to get it onto your Mac.

Mistake 3 · “I committed, so GitHub has my changes.”

Commit = saved locally. Push = sent to GitHub.

Mistake 4 · “I pushed my branch, so Ani’s main branch changed.”

A branch push does not automatically merge that branch into Ani’s main.

Mistake 5 · “I connected Vercel once, so I need to upload the HTML again after every change.”

When the repository is connected through Git integration, Git changes can trigger new deployments automatically.

Chapter 15

Interactive knowledge check

Answer all seven questions. Each one explains the idea after you choose.

1. Samriti has write access and needs the project on her Mac. What should she do?

Clone copies Ani’s repository onto Samriti’s Mac. She already has write permission, so she does not need a fork first.

2. Mishthi has no write permission but wants to contribute. What is the correct flow?

External contribution usually needs both a fork and a clone, then a pull request because she cannot push to Ani’s repository.

3. Where does Fork happen?

Fork creates another GitHub repository under your account. It does not place files on the Mac.

4. Where does Clone place the project?

Clone answers “How do I get this repository onto my Mac?”

5. What sends committed code from your Mac to GitHub?

Commit saves a checkpoint locally. Push sends those commits to the remote (usually origin on GitHub).

6. After GitHub is connected to Vercel, what can happen after a new commit is pushed?

The Git integration watches the connected repository. A push can trigger a new deployment. You keep working from Mac + GitHub.

7. A pull request on a feature branch usually creates which Vercel result first?

PR / branch → Preview. Merge into the production branch (often main) → Production deployment.

A project’s files plus Git history.

Local

Your Mac.

Remote

A repository hosted somewhere such as GitHub.

Fork

Pull

Remote → Mac.

Branch
